# The MusicBrainz probe, committed — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `./gradlew mbProbe -Dsegue.probe.db=<a copy>` prints ADR 55's five blocks over a real graph, and `./gradlew check` runs the same engine offline against a fixture whose totals are known by construction — so someone who doubts ADR 55 re-derives its magnitudes instead of re-deriving its method.

**Architecture:** One pure engine (`MusicBrainzProbe`) over four injected collaborators — a seed source read from an explicit database path, a `MusicBrainzClient`, a `MusicBrainzIdentity`, and the Wikidata-side `SourceAdapter` — plus a renderer producing five tables and a checker asserting invariants over them. Two runs: `MusicBrainzProbeTest` (fixture, in `check`, exact totals) and `MusicBrainzProbeLiveTest` (`@Tag("live")`, structure only). `ProbeDatabase` refuses any path that is not an existing copy. All test source; no production change except one additive method on `StubMusicBrainzServer` (also test source).

**Tech Stack:** Java (toolchain 25, `release 21`), Gradle 9.7.1, JUnit, AssertJ, Jackson 3 (`tools.jackson`), sqlite-jdbc, JDK `HttpServer`.

**Spec:** `docs/superpowers/specs/2026-09-02-mb-probe-design.md`

## Global Constraints

- **`~/.segue/segue.db` is never read, written, opened or copied — by any step, at any time.** The probe refuses it by construction (Task 2) and that refusal is itself tested. No step runs a writing dev task (`ownClaim`, `retractEntity`, any abbreviation — `./gradlew own` resolves to `:ownClaim` and runs). If a live run is wanted, the **owner** copies the database and passes the copy's path; an implementer never does.
- **No network in `./gradlew check`.** The fixture run reaches `StubMusicBrainzServer` on loopback and nothing else. Never call the real MusicBrainz or Wikidata endpoints from any step of this plan; the live class is written, not run, by the implementer.
- **Pure TDD, one behaviour per red→green loop.** Every step names the red it expects and the report quotes what the failure actually said. A compile error is not a red.
- Test names `should<Expected>When<Condition>` with `@DisplayName`.
- **ADRs are immutable.** ADR 55 gets a **dated amendment** only; `git diff -- docs/adr/ | grep '^-' | grep -v '^---'` must be empty. No new ADR.
- **Never `git add -A`.** Stage by explicit path — this worktree shares a repository with parallel sessions.
- Gate, **blocking, never backgrounded**: `SEGUE_REQUIRE_BROWSER=true ./gradlew check --rerun-tasks`. The last recorded baseline is 1050 tests (2026-09-02, #183's plan) — **measure it on `main` rather than trusting it.**
- **Only JDK 25 is installed and Gradle 9.7.1 launches on it.** Plain `./gradlew`. Do NOT set `JAVA_HOME=$(/usr/libexec/java_home -v 21)` — it returns the JDK 25 path with exit 0.
- **Aggregates only.** Nothing the probe prints, and nothing any report or commit message quotes from a live run, may name an entity: no QID, no MBID, no label. Task 1 asserts this of the output; the same rule binds every human-written line about a run (ADR 33, ADR 51).
- **Fixture extensions:** `*.csv`, `*.txt` and `*.db` are gitignored. The fixture is `.json`.
- **House style in `docs/`:** backticked paths, not markdown links — `DocumentationLinksTest` checks every relative link under `docs/**/*.md`, this plan included.
- Never cite a `.superpowers/` path from a committed file.

### Task 1: The engine, the five tables, and the invariants over them

Pure functions and a renderer, driven from hand-built inputs. No I/O, no database, no server.

**Files:**
- Create: `src/test/java/com/robsartin/segue/musicbrainz/MusicBrainzProbe.java` — the engine and renderer
- Create: `src/test/java/com/robsartin/segue/musicbrainz/MusicBrainzProbeEngineTest.java` — this task's loops
- Read only: `docs/adr/0055-what-the-musicbrainz-adapter-refuses.md` (the two tables and the prose block 5 comes from); `src/main/java/com/robsartin/segue/mcp/SegueService.java` lines 252–312 (the three branches the buckets mirror); `port/ExpandResult.java`; `domain/NodeAssertion.java`

**Interfaces:**
- Produces, consumed by Tasks 2–4:
  - `record ProbeInputs(List<NodeRecord> seeds, MusicBrainzClient client, MusicBrainzIdentity identity, SourceAdapter wikidataSide, GraphStore graph)`
  - `record ProbeReport(Sample sample, Map<String,Integer> census, Buckets buckets, Percentiles saving, Cost cost)` with `String render()`
  - `static ProbeReport MusicBrainzProbe.run(ProbeInputs)`
  - `static void MusicBrainzProbe.assertInvariants(ProbeReport)` — the shape checker both runs call

- [ ] **Loop A — the census, RED first.** Write `shouldCountEachRelationTypeOnceWhenSeveralSeedsShareAType`: hand two seeds' `List<ArtistRelation>` to the census function and assert descending-by-count-then-type rows plus a `TOTAL` equal to the relation count. Run it: RED, no such method. Implement the frequency count. GREEN. **The compile error does not count as the red** — once it compiles, plant a wrong total and observe the assertion fire; quote it.
- [ ] **Loop B — the three buckets partition.** Drive `SegueService`'s branches with hand-built inputs: a neighbour present in the `GraphStore`, one absent but in the Wikidata side's `neighbors()`, one absent and undescribed. Assert the three counts and that they sum to the resolved-neighbour total. RED on the sum before the third branch exists.
- [ ] **Loop C — percentiles and block 5.** Per-seed counts of the third bucket → `median ≤ p90 ≤ max`, and `max` equal to the largest per-seed third-bucket count. Block 5's five figures: class-less creations (= bucket three), erasure occurrences, distinct nodes erased, of those with a non-empty `instanceOf`, seeds the shared bound cut (`collected.size() > ExpansionBounds.effective(...)`). RED on `distinct ≤ occurrences` with a planted input where a node is reached twice.
- [ ] **Loop D — the renderer, and the privacy assertion.** `render()` emits the five blocks in the spec's order with the spec's exact column headings. Assert the whole rendered string matches no `Q\d+` and no UUID, and that every non-heading cell is an integer, a percentage, or a MusicBrainz relation type. **Positive control:** feed a seed label and a QID into the inputs and confirm neither reaches the output — then plant a `render()` that prints a seed label, observe the privacy assertion red, quote it, revert.
- [ ] **Loop E — `assertInvariants` is not vacuous.** For each invariant in the spec's §2, build a report that violates exactly it and confirm `assertInvariants` reds naming that invariant. Seven planted violations, seven distinct messages, listed in the report. An invariant with no red is not an invariant.
- [ ] **Step 6 — gate and commit.**

### Task 2: `ProbeDatabase` — the copy is a parameter, and the real database is refused

**Files:**
- Create: `src/test/java/com/robsartin/segue/musicbrainz/ProbeDatabase.java`

**Interfaces:**
- Produces: `static Path ProbeDatabase.require(String propertyValue, String envSegueDb, Path defaultDatabase, Path userHome)` — every input a parameter, so no test touches a real environment. - [ ] **Step 1 — four refusals, each RED first, one loop each.** (a) absent or blank; (b) a path that does not exist — the case that would otherwise let `SqliteAssertionLog` create an empty database and print a table of zeros; (c) a path whose `toRealPath` equals `defaultDatabase`, or lies under `<userHome>/.segue` — assert a **symlink** to the default is refused too, built in a `@TempDir`; (d) `SEGUE_DB` set with the property absent, refused with `SEGUE_DB` named in the message. Quote each red.
- [ ] **Step 2 — the accept path.** An existing file in a `@TempDir` is returned unchanged. This is the one green case, and it is what stops the class refusing everything.
- [ ] **Step 3 — the negative control.** Assert `ProbeDatabaseTest` creates nothing under its own invented home and nothing under `${user.home}`, in the shape `OwnCliTest` asserts it. Plant a `require` that opens the path before refusing → red. Quote; revert.
- [ ] **Step 4 — gate and commit.**

### Task 3: The fixture run — the whole pipeline offline, with a positive control

**Files:**
- Create: `src/test/resources/musicbrainz/probe-fixture.json` — claims plus a declared `expected` block
- Create: `src/test/java/com/robsartin/segue/musicbrainz/MusicBrainzProbeTest.java`
- Modify: `src/test/java/com/robsartin/segue/musicbrainz/StubMusicBrainzServer.java` — add `enqueueBody(String path, String json)` answering `/artist/<mbid>`; the existing queue behaviour is unchanged and the javadoc says both exist and why
- Read only: `ingest/GraphProjector.java`; `sqlite/SqliteAssertionLog.java`; `musicbrainz/StubIdentity.java`; `src/test/resources/musicbrainz/artist-with-relations.json` (the response shape to imitate); `MusicBrainzClientTest`, `MusicBrainzSourceAdapterTest` (they must stay green)

**Interfaces:**
- Consumes `MusicBrainzProbe.run/assertInvariants` (Task 1) and `ProbeDatabase.require` (Task 2).
- The fixture's `expected` object is the only place its totals are written; the test reads them rather than repeating them, so the fixture and its expectation cannot drift apart in two files.

- [ ] **Step 1 — the fixture, small and known by construction.** Roughly 4 seeds (2 `PERSON`, 2 `GROUP`), 3 bridged, ~9 relations across ≥4 distinct types including one `subgroup` and several `member of band`, and ~5 resolved neighbours splitting 2 / 1 / 2 across the three buckets — enough that every block has more than one row and block 3 has no empty bucket. Write the `expected` block by hand from the claims, not from a run.
- [ ] **Step 2 — build the database through the real writer, RED first.** The test writes the fixture's claims into a `SqliteAssertionLog` under `@TempDir`, projects it with `GraphProjector.project(log, new TinkerGraphStore(), IdentityMerge.NONE)`, and hands `ProbeDatabase.require(tempPath, …)` to the probe. Assert the rendered table equals `expected`. RED before the wiring exists; quote.
- [ ] **Step 3 — the stub by path.** Add `enqueueBody(path, json)`; serve each bridged seed's response at `/artist/<mbid>`. Confirm `MusicBrainzClientTest` and the concurrency test are still green — run them by name and say so.
- [ ] **Step 4 — the positive controls, four of them, each a different column.** (a) add one `tribute` relation to a served response → block 2's `TOTAL` ≠ `expected`; (b) move one neighbour from absent to present in the fixture's claims → block 3's first bucket disagrees; (c) drop a neighbour from the Wikidata-side stub's `neighbors()` → block 3's second and third buckets shift; (d) remove one seed's `P434` entry from `StubIdentity` → block 1's `bridged` falls. Each must red on a *different* assertion; quote all four; revert all four. **A fixture edit that reds nothing means that column has no control — say so rather than moving on.**
- [ ] **Step 5 — no network, asserted.** The test constructs `new MusicBrainzClient(stub.baseUri())` and the stub's `requestCount()` equals the number of bridged seeds — so a request that escaped to the real endpoint shows up as a count that does not match. State the count in the report.
- [ ] **Step 6 — gate and commit.**

### Task 4: The live run, the Gradle task, and what ADR 55 gains

- Create: `src/test/java/com/robsartin/segue/musicbrainz/MusicBrainzProbeLiveTest.java` — `@Tag("live")`
- Modify: `build.gradle.kts` — `tasks.register<Test>("mbProbe")`
- Modify: `docs/adr/0055-what-the-musicbrainz-adapter-refuses.md` — a dated amendment, **addition only**
- Modify: `docs/developer-guide.md` — one paragraph in "Why `liveTest` is separate", plus a Contents entry only if the guide's rules require one
- Read only: `MusicBrainzLiveSmokeTest.java` (the shape and the javadoc conventions a live class follows); `app/WikidataMusicBrainzIdentity.java`; `app/SegueConfiguration.java` (how `WikidataSourceAdapter` is built); the `retractEntity` and `ownClaim` task descriptions in `build.gradle.kts` (the `--db`/`$HOME` description shape)

**Interfaces:** consumes Tasks 1–3; produces nothing consumed later.

- [ ] **Step 1 — the live class.** 200 seeds by default (`-Dsegue.probe.seeds` to vary), 100 `PERSON` and 100 `GROUP`, ordered by a **deterministic** pseudorandom function of the QID — state the function in the javadoc and pin it with a unit test in Task 1's class, so two runs over one database draw the same sample. It calls `ProbeDatabase.require`, builds the production `WikidataMusicBrainzIdentity`, `MusicBrainzClient` and `WikidataSourceAdapter`, runs the engine, prints `render()` to stdout and calls `assertInvariants` — **and nothing else.** No figure from ADR 55 appears as an expectation.
- [ ] **Step 2 — the refusal is the live class's own first behaviour.** With no `-Dsegue.probe.db` the class **fails** with `ProbeDatabase`'s sentence rather than skipping. Assert it in the fixture-run test (it is `ProbeDatabase`'s contract, already covered by Task 2) and state in the live class's javadoc that a skip was rejected and why.
- [ ] **Step 3 — the Gradle task.** `tasks.register<Test>("mbProbe")`: `group = "verification"`, `includeTags("live")` filtered to `MusicBrainzProbeLiveTest`, `jvmArgs("--enable-native-access=ALL-UNNAMED")` (`liveTest` does not set it and sqlite-jdbc needs it — say so in a comment), `outputs.upToDateWhen { false }`, `testLogging` showing standard out so the table is visible, and it forwards `segue.probe.db`. The description carries the copy step with `$HOME`, not `~`. **Then run `./gradlew check`** — `build.gradle.kts` is a declared input to `test`, so the suite re-runs; confirm `PackageListsTest` is green (its parser asserts every line mentioning `JavaExec` is a `JavaExec` registration; a `Test` registration is invisible to it, and this step is what proves that rather than assumes it).
- [ ] **Step 4 — ADR 55's dated amendment.** One dated section: the probe behind the figures above is now committed as `MusicBrainzProbeLiveTest`, run by `./gradlew mbProbe`; it regenerates the shape of the tables in this ADR and asserts their structure, not their values; **it revises no decision and adds no figure**, and the figures above stay the 2026-08-30 measurement. Correct nothing else. Verify `git diff -- docs/adr/` shows no deleted line, and `AdrIndexTest` and `DocumentationLinksTest` are green.
- [ ] **Step 5 — the guide.** One paragraph naming `mbProbe`, the copy step, and that the task refuses the real database. No table of figures — the guide cites ADR 55, it does not mirror it.
- [ ] **Step 6 — gate and commit.** Full gate blocking. **Do not run `mbProbe`** — it needs the network and a copy only the owner can make. Report that it was not run, and say what that leaves unverified: that the live class compiles and is discovered by the task is checkable (`./gradlew mbProbe --dry-run`, and the task's test filter matching exactly one class); that the real endpoints still answer in the shape the engine parses is not, and `MusicBrainzLiveSmokeTest` is the existing guard for that half.

## Self-Review

**Spec coverage.** Five-block table shape → Task 1 Loops A/C/D. Structure-not-values assertions → Task 1 Loop E (`assertInvariants`), used by both runs. Privacy as a checkable property of the output → Loop D. Database as a parameter, real one refused, non-existent path refused → Task 2. Offline fixture exercising the real `SqliteAssertionLog` and `GraphProjector` → Task 3 Step 2. Positive control, one per column → Task 3 Step 4. Live run tagged `live`, fails rather than skips → Task 4 Steps 1–2. One Gradle task, with the native-access grant `liveTest` lacks → Step 3. ADR 55 amended not edited, guide paragraph → Steps 4–5. Rejected alternatives → spec.

**Placeholders.** None. The fixture's magnitudes in Task 3 Step 1 are a stated floor ("every block has more than one row, no empty bucket"), not a TODO; the seed-ordering function in Task 4 Step 1 is required to be written down and pinned by a test rather than left to the implementer's memory.

**Type consistency.** `ProbeInputs`/`ProbeReport`/`MusicBrainzProbe.run`/`assertInvariants` are produced in Task 1 and consumed by name in Tasks 3 and 4. `ProbeDatabase.require(String, String, Path, Path)` is produced in Task 2 and called in Tasks 3 and 4 with all four arguments supplied by the caller — no ambient environment read anywhere. `StubMusicBrainzServer.enqueueBody(String, String)` is added in Task 3 alongside the existing one-argument form, which stays.

**What this plan does not do.** It does not re-run ADR 55's measurement, and it must not be read as re-deriving the figures: it commits the instrument. A live run producing today's numbers is the owner's act, on the owner's copy, and would be its own issue.
